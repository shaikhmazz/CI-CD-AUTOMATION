1. INTRODUCTION
================================================================================
1.1 Background of the Study:
Modern software engineering has transitioned rapidly from monolithic release
cycles and isolated development-operations silos to Agile methodologies and
Continuous Integration / Continuous Deployment (CI/CD). Traditionally, enterprise
Java web applications were built, packaged, tested, and released manually by
operational teams. Developers compiled code locally on heterogeneous machines,
transferred Web Application Archives (WAR files) via manual FTP/SCP to virtual
machines or physical Tomcat servers, and restarted services during late-night
maintenance windows.

This legacy approach suffered from severe friction, high deployment latency,
configuration drift, and high defect escape rates. With the advent of cloud
computing, microservices, containerization (Docker), container orchestration
(Kubernetes), and Infrastructure as Code (Terraform), engineering organizations
require fully automated pipelines. An automated CI/CD pipeline ensures that every
commit to the source code management system (SCM) is deterministically validated,
tested, security scanned, compiled into immutable artifacts, and rolled out to
cloud environments with zero downtime.

1.2 Problem Statement:
In manual or semi-automated deployment workflows for Java enterprise applications,
organizations encounter critical challenges:
1. Inconsistent Build Environments: Builds vary depending on local workstation
   configurations, leading to the notorious 'it works on my machine' defect.
2. Undetected Vulnerabilities & Security Risks: Code smells, security flaws
   (e.g., OWASP Top 10 vulnerabilities), and dependencies with known CVEs are often
   detected only after production deployment.
3. Lack of Artifact Traceability: Without a centralized binary management system
   like JFrog Artifactory, binaries lack build metadata, making rollbacks and
   compliance auditing complex.
4. Deployment Downtime: Manually stopping and replacing WAR files on standalone
   application servers incurs significant operational downtime and disruption to
   active users.
5. Manual Cloud Provisioning: Manually deploying virtual machines, configuring
   security groups, and installing tools is error-prone, irreproducible, and
   time-consuming.

1.3 Objectives:
The primary objectives of this project are:
- To automate the entire software delivery lifecycle from Git commit to Kubernetes
  deployment on AWS.
- To enforce a 'Shift-Left' DevSecOps strategy by integrating SonarQube static code
  quality gates and Aqua Trivy container vulnerability scanning directly into the
  pipeline.
- To guarantee hermetic build environments and binary traceability using Apache
  Maven and JFrog Artifactory repository management.
- To package the multi-module Java application into an optimized, secure Docker
  container based on Apache Tomcat.
- To achieve zero-downtime rolling updates in a production-grade Kubernetes cluster
  using declarative deployment and service manifests.
- To implement Infrastructure as Code (IaC) using Terraform to provision the
  complete AWS host environment and automated cloud-init bootstrap scripts.
- To establish automated feedback loops via comprehensive HTML email alerts
  notifying stakeholders of build outcomes.

1.4 Motivation:
Modern cloud-native systems prioritize agility, security, and reliability.
Automating the CI/CD pipeline eliminates human error, reduces Mean Time to
Resolution (MTTR), and frees engineering resources from repetitive manual tasks.
Furthermore, by introducing automated security scanning (SAST and Container CVE
inspection) before artifacts are promoted to production registries, the security
posture of the organization is reinforced early in the development lifecycle.

1.5 Scope of Work:
The scope of this project encompasses:
- Design and implementation of a 14-stage declarative Jenkins pipeline.
- Building a multi-module Java 17 application with a core backend JAR ('server')
  and web frontend WAR ('webapp').
- Configuring SonarQube static analysis and quality gates halting builds on
  security or quality failure.
- Publishing released and snapshot binaries to JFrog Artifactory along with build
  environment metadata.
- Containerizing the web application with Docker and scanning image layers with
  Aqua Trivy for HIGH and CRITICAL vulnerabilities.
- Rolling deployment of the container image to an AWS Kubernetes cluster with
  LoadBalancer service exposure on port 8080.
- Automated provisioning of the AWS EC2 instance (m7i-flex.large) in region
  ap-south-2, security groups, and automated bootstrap scripts using Terraform.

1.6 Methodology Overview:
1. Source Control Management: Developers push code to the GitHub repository.
2. Pipeline Trigger & Hermetic Build: Jenkins executes clean workspace, pulls the
   source, and triggers Maven to compile and run JUnit tests.
3. Static Application Security Testing: SonarQube analyzes source code; pipeline
   validates Quality Gate thresholds.
4. Artifact Repository Management: Artifacts are deployed to JFrog Artifactory
   with build information.
5. Containerization & Vulnerability Scanning: Docker builds the Tomcat image,
   followed by an Aqua Trivy CVE security audit.
6. Continuous Deployment: Kubernetes applies updated manifests and executes a
   zero-downtime rolling update.
7. Notification & Observability: Formatted HTML emails notify stakeholders of build
   success or failure.

1.7 Organization of the Report:
Chapters 1 through 9 provide in-depth literature review, system analysis, algorithm
design, architectural blueprints, implementation details, screenshot verification,
and experimental results.

4. PROPOSED METHODOLOGY / PROPOSED ALGORITHM
================================================================================
4.1 System Architecture:
- AWS EC2 host (m7i-flex.large / Ubuntu 22.04) running Jenkins, Docker, SonarQube.
- JFrog Artifactory storing WAR archives and build metadata.
- Kubernetes cluster executing RollingUpdate of regapp-deployment with LoadBalancer
  service on port 8080.

4.2 Design Flow / Methodology Steps:
1. Clean Workspace (cleanWs)
2. Checkout SCM (main branch via github-token-auth)
3. Build Application (mvn clean package)
4. Test Application (mvn test)
5. SonarQube Analysis (mvn sonar:sonar)
6. Quality Gate (waitForQualityGate)
7. Artifactory Configuration (rtServer)
8. Deploy Artifacts (rtMavenRun webapp/pom.xml)
9. Publish Build Info (rtPublishBuildInfo)
10. Build & Push Docker Image (maxain27/register-app-pipeline:1.0.0-${BUILD_NUMBER})
11. Trivy Vulnerability Scan (aquasec/trivy HIGH,CRITICAL)
12. Cleanup Artifacts (docker rmi)
13. Deploy to Kubernetes (kubectl apply regapp-deploy.yml, regapp-service.yml)
14. Post Actions (Email alert: groovy-html.template)

4.3 Proposed Algorithm (Algorithm 1):
--------------------------------------------------------------------------------
Input: Git commit event C on branch B = 'main'
Output: Kubernetes deployment status S in {SUCCESS, FAILED}

1.  INITIALIZE pipeline context on Jenkins agent;
2.  EXECUTE cleanWs();
3.  CLONE repository from GitHub using credential 'github-token-auth';
4.  EXECUTE 'mvn clean package';
    IF build_exit_code != 0 THEN GOTO STEP 16 (FAILURE);
5.  EXECUTE 'mvn test';
    IF test_failures > 0 THEN GOTO STEP 16 (FAILURE);
6.  EXECUTE 'mvn sonar:sonar' WITH CREDENTIAL 'SonarQube-Token';
7.  QG = waitForQualityGate();
    IF QG.status == 'ERROR' AND abortPipeline == true THEN GOTO STEP 16 (FAILURE);
8.  CONNECT TO JFrog Artifactory ('jfrog-server');
9.  DEPLOY 'webapp/target/webapp.war' TO JFrog ('libs-release-local');
10. PUBLISH build metadata via rtPublishBuildInfo;
11. BUILD Docker image: image = docker.build('maxain27/register-app-pipeline:' + T);
    PUSH image with tags [T, 'latest'] to Docker Hub;
12. EXECUTE Trivy container scan on 'maxain27/register-app-pipeline:latest' for severity [HIGH, CRITICAL];
13. PRUNE local Docker image cache ('docker rmi');
14. AUTHENTICATE with Kubernetes cluster via 'kubernetes' kubeconfig credential;
    APPLY 'regapp-deploy.yml' AND 'regapp-service.yml';
    EXECUTE 'kubectl rollout restart deployment.apps/regapp-deployment';
15. NOTIFY via emailext: Status = SUCCESS, Send groovy-html.template TO NOTIFICATION_EMAIL;
    TERMINATE WITH EXIT CODE 0;
16. (FAILURE HANDLER) NOTIFY via emailext: Status = FAILED, Send logs TO NOTIFICATION_EMAIL;
    TERMINATE WITH EXIT CODE 1;

I.1 Declarative Jenkinsfile:
--------------------------------------------------------------------------------
pipeline {
    agent any

    tools {
        maven 'Maven'
    }

    environment {
        APP_NAME = "register-app-pipeline"
        RELEASE = "1.0.0"
        DOCKER_USER = "maxain27"
        DOCKER_CRED_ID = 'dockerhub' // Updated to match Jenkins credentials ID
        IMAGE_NAME = "${DOCKER_USER}/${APP_NAME}"
        IMAGE_TAG = "${RELEASE}-${BUILD_NUMBER}"
        SONAR_HOST_URL = "http://16.112.180.109:9000"
        JFROG_URL = "http://16.112.180.109:8082/artifactory"
        NOTIFICATION_EMAIL = "shaikhmazz125@gmail.com"
    }

    stages {
        stage("Cleanup Workspace") {
            steps {
                cleanWs()
            }
        }

        stage("Checkout from SCM") {
            steps {
                git branch: 'main', 
                credentialsId: 'github-token-auth', 
                url: 'https://github.com/shaikhmazz/CI-CD-AUTOMATION.git'
            }
        }

        stage("Build Application") {
            steps {
                sh "mvn clean package"
            }
        }

        stage("Test Application") {
            steps {
                sh "mvn test"
            }
        }

        stage("SonarQube Analysis") {
            steps {
                script {
                    withSonarQubeEnv(credentialsId: 'SonarQube-Token') { 
                        sh "mvn sonar:sonar -Dsonar.host.url=${SONAR_HOST_URL}"
                    }
                }    
            }
        }

        stage("Quality Gate") {
            steps {
                script {
                    waitForQualityGate abortPipeline: false, credentialsId: 'SonarQube-Token'
                }    
            }
        }

        stage('Artifactory Configuration') {
            steps {
                rtServer (
                    id: "jfrog-server",
                    url: "${JFROG_URL}",
                    credentialsId: "jfrog"
                )

                rtMavenDeployer (
                    id: "MAVEN_DEPLOYER",
                    serverId: "jfrog-server",
                    releaseRepo: "libs-release-local",
                    snapshotRepo: "libs-snapshot-local"
                )

                rtMavenResolver (
                    id: "MAVEN_RESOLVER",
                    serverId: "jfrog-server",
                    releaseRepo: "libs-release",
                    snapshotRepo: "libs-snapshot"
                )      
            }
        }

        stage('Deploy Artifacts') {
            steps {
                rtMavenRun (
                    tool: "Maven",
                    pom: 'webapp/pom.xml',
                    goals: 'clean install',
                    deployerId: "MAVEN_DEPLOYER",
                    resolverId: "MAVEN_RESOLVER"
                )
            }
        }

        stage('Publish Build Info') {
            steps {
                rtPublishBuildInfo (
                    serverId: "jfrog-server"
                )
            }
        }

        stage("Build & Push Docker Image") {
            steps {
                script {
                    docker.withRegistry('', DOCKER_CRED_ID) {
                        def docker_image = docker.build("${IMAGE_NAME}:${IMAGE_TAG}")
                        docker_image.push("${IMAGE_TAG}")
                        docker_image.push('latest')
                    }
                }
            }
        }

        stage("Trivy Scan") {
            steps {
                script {
                    sh "docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy image ${IMAGE_NAME}:latest --no-progress --scanners vuln --exit-code 0 --severity HIGH,CRITICAL --format table"
                }
            }
        }

        stage('Cleanup Artifacts') {
            steps {
                script {
                    sh "docker rmi ${IMAGE_NAME}:${IMAGE_TAG} || true"
                    sh "docker rmi ${IMAGE_NAME}:latest || true"
                }
            }
        }

        stage('Deploy to Kubernetes') {
            steps {
                script {
                    dir('Kubernete') {
                        kubeconfig(credentialsId: 'kubernetes', serverUrl: '') {
                            sh 'kubectl apply -f regapp-deploy.yml'
                            sh 'kubectl apply -f regapp-service.yml'
                            sh 'kubectl rollout restart deployment.apps/regapp-deployment'
                        }
                    }
                }
            }
        }
    }

    post {
        failure {
            emailext (
                body: '''${SCRIPT, template="groovy-html.template"}''', 
                subject: "${env.JOB_NAME} - Build # ${env.BUILD_NUMBER} - Failed", 
                mimeType: 'text/html',
                to: "${NOTIFICATION_EMAIL}"
            )
        }
        success {
            emailext (
                body: '''${SCRIPT, template="groovy-html.template"}''', 
                subject: "${env.JOB_NAME} - Build # ${env.BUILD_NUMBER} - Successful", 
                mimeType: 'text/html',
                to: "${NOTIFICATION_EMAIL}"
            )
        }
    }
}

#!/bin/bash
sudo apt update -y
wget -O - https://packages.adoptium.net/artifactory/api/gpg/key/public | tee /etc/apt/keyrings/adoptium.asc
echo "deb [signed-by=/etc/apt/keyrings/adoptium.asc] https://packages.adoptium.net/artifactory/deb $(awk -F= '/^VERSION_CODENAME/{print$2}' /etc/os-release) main" | tee /etc/apt/sources.list.d/adoptium.list
sudo apt update -y
sudo apt install temurin-17-jdk -y
/usr/bin/java --version
curl -fsSL https://pkg.jenkins.io/debian-stable/jenkins.io-2023.key | sudo tee /usr/share/keyrings/jenkins-keyring.asc > /dev/null
echo deb [signed-by=/usr/share/keyrings/jenkins-keyring.asc] https://pkg.jenkins.io/debian-stable binary/ | sudo tee /etc/apt/sources.list.d/jenkins.list > /dev/null
sudo apt-get update -y
sudo apt-get install jenkins -y
sudo systemctl start jenkins
sudo systemctl status jenkins

##Install Docker and Run SonarQube as Container
sudo apt-get update
sudo apt-get install docker.io -y
sudo usermod -aG docker ubuntu
sudo usermod -aG docker jenkins  
newgrp docker
sudo chmod 777 /var/run/docker.sock
docker run -d --name sonar -p 9000:9000 sonarqube:lts-community

#install trivy
sudo apt-get install wget apt-transport-https gnupg lsb-release -y
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/trivy.gpg] https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" | sudo tee -a /etc/apt/sources.list.d/trivy.list
sudo apt-get update
sudo apt-get install trivy -y

#install maven
sudo apt-get update
sudo apt install openjdk-17-jdk -y
sudo apt install maven -y

## @formatter:off
